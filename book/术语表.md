# 术语表

## 术语

| 术语（中文） | 英文 | 定义/约定 | 首次出现章节 |
|---|---|---|---|
| 前线部署工程师（FDE） | Forward Deployed Engineer | 驻在客户现场，把技术（本书侧重 AI 和智能体）落地成客户业务成果的工程师。首次出现写全称「前线部署工程师（Forward Deployed Engineer，FDE）」，此后写 FDE。不写「前沿部署工程师」「现场工程师」 | 第 1 章 |
| 贯穿案例 | — | 全书共用的真实项目：VectA 为一家水果供应链企业做的 AI 部署。不写「综合案例」「大作业」 | 第 1 章 |
| 实训 | — | 每周 2 课时的动手环节，按每章「本周实训」完成。不写「实验」「上机」 | 第 1 章 |
| VectA | — | 面向水果供应链企业的 AI 业务运营平台，本书实训用它的账号和演示账套 | 第 1 章 |
| DeepSeek Harness（dsh） | DeepSeek Harness | DeepSeek 开源的智能体宿主（命令行工具），本书的实训平台 | 第 1 章 |
| 智能体 | agent | 能按任务说明处理材料、给出结果，并在获准时执行某些动作的 AI 软件 | 第 1 章 |
| 人工智能（AI） | artificial intelligence (AI) | 本章语境下，指能按给定材料整理或生成信息的工具。 | 第 1 章 |
| 交付 | delivery | 把可用方案、操作说明和待核事项交给客户团队，让他们能接着使用。 | 第 1 章 |
| 售前演示人员 | pre-sales demo presenter（本章工作性译名） | 在客户决定是否购买前介绍产品能力的人。本章按工作阶段和目标区分该角色与 FDE；团队职责可能重叠。 | 第 1 章 |
| 成功标准 | success criteria | 开工前约定用哪些可观察证据判断目标问题是否得到改善。 | 第 1 章 |
| 原型 | prototype | 用来先试想法的初步版本。 | 第 1 章 |
| 端到端测试 | end-to-end test (E2E test) | 从输入开始，沿实际操作顺序检查到业务结果的整条流程。 | 第 1 章 |
| 正式上线 | production rollout / go-live | 方案正式交给客户，在日常业务中使用；与演示或受控测试区分。 | 第 1 章 |
| 普通软件 | conventional software | 按预先写好的规则重复处理任务的软件；适合规则稳定、输入清楚的步骤。 | 第 2 章 |
| 提示 | prompt | 给智能体的文字指令，说明本次要完成的工作和要求。 | 第 3 章 |
| 任务说明 | task specification | 把目标、背景、限制和输出格式写在一起的工作交代。 | 第 3 章 |
| 上下文 | context | 帮助理解任务的业务背景、已有材料和必要条件。 | 第 3 章 |
| 结构化输出 | structured output | 按事先约定的字段或栏目组织结果。 | 第 3 章 |
| 业务材料 | business materials | 与任务有关、可回查的业务记录、流程说明、规则和经确认的纪要；使用前应核对来源、范围和版本。 | 第 4 章 |
| 来源追溯 | provenance | 从回答中的事实找到支持它的材料及具体位置；来源还须适用于当前业务和时间。 | 第 4 章 |
| 检索增强生成（RAG） | Retrieval-Augmented Generation | 先从指定资料中检索相关内容，再让智能体据此组织回答的做法；本章只讲概念，不展开技术。 | 第 4 章 |
| 工具动作 | tool action | 智能体通过获准的客户系统接口读取信息或提交操作的动作。接口是软件间传递信息或执行操作的入口。 | 第 5 章 |
| 只查询动作 | read-only action | 通过客户系统工具读取已有信息，不创建、修改或删除业务记录，也不向外部对象发送内容；仍须检查访问权限。未保存、未发送的临时文字不属于这组系统动作。 | 第 5 章 |
| 会改变记录的动作 | record-changing action | 本章对客户系统工具动作的分类名：创建、修改、删除业务记录，或向外部对象发送内容。发送未必改写系统记录，但会造成外部影响。 | 第 5 章 |
| 人工确认 | human approval | 由有权限的人检查具体操作对象、变更内容、依据和影响，并同意本次操作。 | 第 5 章 |
| 任务评测 | task-level evaluation | 用一组代表性问题、预期行为和评分标准检查智能体是否完成具体业务任务。 | 第 6 章 |
| 测试用例 | test case | 围绕一种业务情境记录的问题、预期、实际回答、评分和证据。 | 第 6 章 |
| 评分标准 | scoring rubric | 评分者事先共同采用的可观察判断规则。 | 第 6 章 |
| 回归测试 | regression test | 修改任务说明或材料后，重跑旧测试以检查原有表现是否退步。 | 第 6 章 |
| 发布门槛 | release criteria | 客户和 FDE 事先约定的最低交付条件。 | 第 6 章 |
| 业务流程 | business process | 一项工作从开始到完成所经过的一连串动作，以及动作之间的先后关系。 | 第 7 章 |
| 账套 | ledger / account set | 一套单独保存的业务数据空间；课堂使用时须与客户生产数据隔离。 | 第 7 章 |
| 业务角色 | business role | 一个人在业务链上承担的工作责任；指工作，不指真实姓名或职位。 | 第 7 章 |
| 业务单据 | business document | 说明某一步业务发生了什么的凭证，可以是纸张或电子文件。 | 第 7 章 |
| 系统记录 | system record | 软件中保存、之后可以查询的一条业务数据。 | 第 7 章 |
| 批次 | lot / batch | 一批可以单独追踪的货；即使商品名和日期相同，也不能据此与另一批合并。 | 第 7 章 |
| 翻箱（重新分装） | repacking | 把原包装的货按需要分成新的包装规格，并记录投入和实点产出。 | 第 7 章 |
| 现状流程图 | current-state process map | 经客户核实后，按当前实际做法绘制并标出步骤、角色、单据和交接的图；课堂合成数据只支持绘制复原草图。 | 第 7 章 |
| 交接点 | handoff point | 工作从一个角色交到另一个角色、并需要传递货物或信息的位置。 | 第 7 章 |
| 等待点 | waiting point | 一步完成后，下一步要等人或等材料才能继续的位置；无时间记录时不推断等待时长。 | 第 7 章 |
| 客户痛点 | customer pain point | 实际工作中反复出现、让人多花力气、容易出错或难以继续的一处不便；须回到流程和证据核对。 | 第 8 章 |
| 基线 | baseline | 开始解决问题之前，实际工作所处的状态；须来自可核对的记录或观察，没有证据时注明待补。 | 第 8 章 |
| 问题说明 | problem statement | 一页以内的工作交代，说明当前现状、期望目标、数据来源和本次不处理的范围。 | 第 8 章 |
| 本次不处理的范围 | out-of-scope items | 明确本轮工作暂不承担的任务或判断，用来限定范围；不表示以后永远不做。 | 第 8 章 |
| 本体（业务模型） | ontology | 本章沿用贯穿案例项目的用法，指整理业务对象、关系和动作的模型；不假设其他公司都使用此名称。 | 第 9 章 |
| 业务对象 | business object | 业务中需要持续识别和回查的内容，如单据、商品、批次或仓库。 | 第 9 章 |
| 业务关系 | business relationship | 有记录支持的对象间联系，须说明关系含义并能指回来源。 | 第 9 章 |
| 业务动作 | business action | 业务中发生的变化，如入库、重新分装或出库；单据是记录，不等同于动作。 | 第 9 章 |
| 业务关系图 | business relationship graph | 用节点表示对象或动作、用有标签的连线表示关系，支持从结果回查来源的图。 | 第 9 章 |
| 包装换算关系 | packaging conversion rule | 说明商品及其包装单位如何换算的业务规则；须核对适用商品、规格和来源，不作无范围的全局固定值。 | 第 9 章 |
| 受控流程 | controlled workflow | 把业务材料到系统结果的步骤、负责人及停止和确认边界说清的工作路线。 | 第 10 章 |
| 提案 | proposal | 智能体根据业务材料整理、供人核对的候选内容；未经有权限的人确认，不作为已登记记录。 | 第 10 章 |
| 回执 | receipt / acknowledgement | 操作后说明处理结果、对应记录位置及仍待处理事项的反馈。 | 第 10 章 |
| 无 | — | 本章使用的术语已列在现有术语表中，未引入需登记的新术语。 | — |
